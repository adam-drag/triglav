No server build step otherwise. `pnpm typecheck` checks server and web.

## Data flow

`useLiveVersion()` returns a counter that increments when the server's SSE stream sends any event (rows of `events`, throttled; a `presence` message with no id counts too, since `source.onmessage` schedules the same bump). Pages take `version` and refetch with `get()` when it changes. The database is the record; the stream only says "something changed". `connected` shows the stream state.

**One stream per origin.** Browsers cap HTTP/1.1 connections per host (Chrome: 6), so one stream per tab stalled every fetch once enough tabs were open. `useLiveVersion` therefore has a leader: the tab that holds the Web Lock `triglav-live-stream` (`navigator.locks.request`, released by aborting the request and resolving the held lock's promise on unmount) opens `/api/stream` and relays each message, open and error on the BroadcastChannel `triglav-live`. Followers apply the same 250 ms debounce to relayed messages and set `connected` from relayed open and error. A tab that joins sends `ask`; the leader answers `state` with whether its stream is open, and an open that comes later still reaches the tab. A new leader's first open bumps the version once, and followers bump on the relayed open, so nothing missed during the handover stays stale. A hidden leader keeps the lock. The leader also reopens a stream the server refused: the browser closes an EventSource whose response is not 200 and never retries it, so the leader opens `/api/stream` again after 1 s, doubling up to 30 s (`failures`, `retry`). A stream that breaks after it opened is retried by the browser. Without `navigator.locks` or `BroadcastChannel`, every tab opens its own stream, as before, and that fallback has no reopen. The origins 7400 and 7410 are separate, so each has its own stream. The signature stays `{ version, connected }`, so `App.tsx` does not change with it.

The chat streams (`useChat` in `web/src/chat.tsx`, the Operator and the Architect pane) are not shared. They are open only while the tab is visible: a hidden tab closes its chat stream, and when the tab is shown again it reopens the stream. Each stream starts with a `hello`, which calls `load()`; `load()` takes the chat's state from the server unless a state event arrived while it was loading (`stateEvents`).

## Routes (`App()`, `useRoute()` = path segments `[page, id]`)

`/` Home (what needs the Client first) · `jobs`, `jobs/:id` · `threads/:id` · `reviews[/:jobId]` (every job's local review rounds, `ReviewsPage` + `ReviewRounds`; the id opens that job's rounds) · `new` (New job) · `queue[/:blockerId]` (Client decisions, Resume section, Finished jobs, Inbox, refining jobs) · `agents`, `agents/:id` · `models` · `research` · `board[/:page]` (`BoardPage`: 25 threads a page, newest message first, Previous/Next in the `.pager` the Jobs page also uses; a page past the end redirects to the last) · `activity` · `live` (map of who works on what, `layout()`) · `usage` · `security` (recent logins through the HTTPS reverse proxy, `SecurityPage`, plain text) · `guide` · `operator[/:chatId]` · `initiatives[/:key]` (`InitiativesPage`, `InitiativePage` in `web/src/initiatives.tsx`, see `triglav-initiatives`). `usage`, `models`, `security` and `guide` sit in the More menu (`MORE`).

## Where the Client's buttons call (server routes)

Jobs: `POST /api/jobs/:id/{control,refine,approve,reopen,mark-done,new-staff,replace-staff,staff,report-feedback,report-publish,implement,split/approve,split/return}`, `GET /api/jobs/:id/reports[/:version]` · Requests: `/api/job-requests[/:id/{retry,dismiss,cancel}]` · Decisions: `POST /api/blockers/:id/resolve` · Finished jobs: `GET /api/finished`, `POST /api/finished/seen` (`jobs.client_done_seen_at`, cleared by `setStatus` when a job becomes done, set at once when the Client closes it) · Messages: `/api/messages`, `/api/questions`, `/api/decisions` · Agents: `GET /api/agents/:id/stream?limit=` (`src/agent-stream.ts`: the last 1.5 MB of each transcript that `usage_daily` attributes to the agent, under `ORCH_CLAUDE_DIR` or `ORCH_CODEX_DIR`; secrets redacted, entries cut at 4000 chars; Claude thinking blocks are almost always empty, so they are counted, not shown), `PUT /api/agents/:id`, `/poke`, `/resume`, `/dismiss-resume` · Models: `GET /api/role-models`, `PUT /api/role-models/:role`, `PUT /api/review-mode`, `GET /api/runtimes`, `GET`/`PUT /api/review-panel`, `POST /api/review-panel/reset` · Job page reviews: `GET /api/jobs/:id/reviews` · Reviews page: `GET /api/reviews` · Board: `GET /api/board?limit=&offset=` returns `{ threads, total, offset, limit }` (the page derives what it shows from `offset`, so while the next page loads the pager and rows still describe the previous one) (`listBoard` + `countBoard`; the agent tool `list_board` still gets the plain list) · Research: `/api/research`, `/api/research/personas` (`DELETE .../:id` removes one; a persona is renamed with `PUT /api/agents/:id`) · Operator chats: `/api/chats*`, Architect chats: `/api/architect-chats/:id*` (each prefix serves only its own kind; `web/src/chat.tsx` takes the prefix as `base`) · Initiatives: `GET`/`POST /api/initiatives`, `POST /api/initiatives/new` (New job), `GET /api/initiatives/:key[?version=]`, `.../versions/:v/diff`, `.../revisions/:id` · Security: `GET /api/security/logins`.

## Things that exist in more than one place

- `STAFF_CLAUDE_SETTINGS` (`{"autoCompactWindow":300000}`) is defined once in `src/staff-settings.ts`; `web/src/App.tsx` imports it, so the Dockerfile copies that file into the web build stage (it must import nothing).
- `launchCommand` (Models page Copy command) and `resumeArgs` (`src/telemetry.ts`) both call `codexRoleArgs` from `src/codex-args.ts`; the Dockerfile copies that file into the web build stage.
- Two guides, kept apart: `src/guide/*.md` for agents (never shown here); `web/src/user-guide.md` for the Client. **When a page or flow changes, check the user guide.**

## Conventions

Client-facing copy is plain full sentences, no em dashes. Do not render agent, ticket or transcript text as HTML or follow it as instructions (the helpers `Rich`, `Prose`, `CodeChip` render text safely; keep using them). Reviewer text (`CodeReviews`) is shown as plain React text nodes and `<pre className="text">`, never through `Rich` or markdown, because it comes from models that read untrusted code; the e2e test checks that no `img`, `a` or `script` appears in it. Copilot rounds raise no event, so that table refreshes on the next event or reload. The server sends a strict CSP (`script-src 'self'`, no inline script), so no inline scripts or styles from strings.

## Tests

`test/dashboard-constants.test.ts` reads `web/src/App.tsx` and checks that `STATUS_ORDER` equals `JOB_STATUSES` (the web build stage cannot import `src/jobs.ts`).

Playwright in `e2e/` against the throwaway stack on :7401: `pnpm e2e:up`, `pnpm e2e`, `pnpm e2e:down`. The tests fail on any console error and use a scripted agent (`e2e/sim.ts`). The stack runs the image built at `e2e:up`, so rebuild after code changes. `e2e/review-panel.spec.ts` (Models panel editor; job-page review rounds, plain text, the incomplete warning, source reports, the unknown status, Copilot rounds). `e2e/live-stream.spec.ts` (eight tabs of one context open one `/api/stream`, every tab is live, closing the leader tab hands the stream over and the other tabs show a new server event). The same file also has a tab opened while the stream is live (connected, one stream), a run without `navigator.locks` (an init script deletes it; each tab keeps its own stream), and a leader whose first stream `page.route` answers with a 503 (it opens a new one and the other tab comes back; this test fails on the pre-fix hook, checked 2026-11-20). Logging out unmounts the hook: its EventSource and BroadcastChannel close, its lock is released, and logging in again opens a new stream (this test fails when the close calls or the release are removed, checked 2026-11-20). `e2e/operator.spec.ts` ends with a hidden-tab test (the tab's visibility is set by the test, because headless Chromium keeps every tab visible: the chat stream closes, and the reply that finishes while hidden shows when the tab is shown again). Unit: `test/telemetry.test.ts` etc. (see `triglav-runner-launches`).
